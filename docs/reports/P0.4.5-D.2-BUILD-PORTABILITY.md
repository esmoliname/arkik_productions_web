## 4. Portability assessment

Business logic (`api/_lib/logic.js`, `service.js`, `repo.js`, SQL, frontend) is
provider-independent. Coupling exists only in:
- Transport: Vercel serverless `(req,res)` + `vercel.json` rewrites/headers.
- Data: `@neondatabase/serverless` (WebSocket proxy) — standard PG otherwise.

Viability:
- Vercel (Node 22 serverless): native, no changes.
- Containers/PaaS (Render, Railway, Fly, Cloud Run): high portability — reuse
  `scripts/dev-server.js` router as production entrypoint, set `TRUST_PROXY=true`,
  enable `SECURE_COOKIES=1` when TLS is terminated, configure headers/rewrites in
  server or proxy. Optionally swap `@neondatabase/serverless` for `pg` if leaving Neon.
- Cloudflare Workers/Pages: low-medium — requires router/adaptador (Hono or Web-to-Node
  bridge), per-request pool instantiation (module-level singleton fails across I/O
  contexts), and `nodejs_compat` for scrypt/Buffer (cost=16384 may approach free-tier
  CPU limits).

No provider migration performed in D.2 (per prompt).

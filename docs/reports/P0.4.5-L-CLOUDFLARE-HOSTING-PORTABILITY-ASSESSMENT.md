## 1. Dictamen

**`PORTABLE — MODERATE ADAPTATION`**

Arkik es portable a Cloudflare Pages + Workers, pero requiere una capa de adaptación HTTP de tamaño moderado. La lógica de negocio, la autenticación, la capa de datos y las consultas SQL son independientes de la plataforma y no necesitan reescritura. El esfuerzo se concentra en la capa de transporte HTTP (handlers, CORS, cookies, IP, env) y en la reestructuración de rutas de archivo.

## 2. Inspección de arquitectura actual

### Modelo de ejecución
- **Vercel Serverless Functions** (Node.js, `api/**/*.js`), file-based routing. Cada archivo exporta `module.exports = withCors(handler)` con firma `(req, res)`.
- **20+ endpoints** en `api/` (health, ready, pricing, admin/*, availability, bookings/*).
- **Capa compartida** en `api/_lib/`: auth, config, cors, db, log, logic, ratelimit, registry, repo, respond, service.

### Dependencias de plataforma (Vercel/Node)
- `req`/`res` de Node.js HTTP (status, json, setHeader, end, socket).
- `process.env` (configuración lazy en `config.js`).
- `process.env.VERCEL` / `VERCEL_ENV` para IP confiable y cookies seguras.
- `req.socket.remoteAddress` para IP del cliente.
- Vercel pre-parsea `req.body` (JSON).

### Imports de módulos Node.js
- `crypto` (auth.js: scryptSync, randomBytes, timingSafeEqual, createHmac, createHash; service.js: randomBytes).
- `URL` (db.js: `new URL()`).
- `Buffer` (respond.js readBody).
- **No** se usan `fs`, `http`, `https`, `net`, `tls`, `stream`, `events`, `os`, `path`, `child_process`.

### Conexiones PostgreSQL
- `@neondatabase/serverless` (`Pool`, `Client`, dynamic `import()`).
- Patrón: pool max:1 por request, transacciones con SET LOCAL timeouts.
- Variables: `DATABASE_URL` (runtime, pooled), `DIRECT_DATABASE_URL`/`DIRECT_ADMIN_DATABASE_URL` (solo CLI, fuera de runtime).

### Criptografía
- scrypt (PINs), HMAC-SHA256 (sesiones), SHA-256 (checksums), randomBytes. Todas disponibles en Workers vía Node compat (`crypto` soportado nativamente).

### Cookies / sesiones / CORS
- Cookie `__Host-session` o `arkik_session`, HttpOnly, Secure condicional, SameSite=Strict, Max-Age 900.
- CORS en `cors.js` (applyCors, withCors wrapper, preflight OPTIONS).
- CSP y headers de seguridad en `vercel.json` (HSTS, X-Frame-Options, etc.).

## 3. Compatibilidad con Cloudflare

### Cloudflare Pages + Functions
- Pages Functions usan el directorio `/functions` (no `/api`) y exportan `onRequest(context)` (Web Request/Response estándar).
- Soporte de Node.js compat vía flag `nodejs_compat` (o compat date = 2026-08-04, que lo habilita por defecto).
- `crypto`, `Buffer`, `URL`, `process`, `Events`, `Stream`, `Timers`, `Zlib` están soportados nativamente (??).
- `@neondatabase/serverless` es compatible con Workers (documentado por Neon y Cloudflare).

### Hyperdrive vs Neon serverless driver
- **Hyperdrive** (recomendado por Cloudflare) usa TCP con `pg`/`postgres.js`. Requiere cambiar el driver y crear un binding Hyperdrive por entorno. Proporciona pooling global.
- **Neon serverless driver** (`@neondatabase/serverless`) funciona sobre HTTP/WebSocket en Workers sin Hyperdrive. Mantiene el driver actual.
- **Recomendación:** mantener `@neondatabase/serverless` en la fase inicial (sin cambios de driver ni Hyperdrive) para minimizar riesgo. Evaluar Hyperdrive después si la latencia lo exige (requiere cambiar `db.js` y agregar binding).
- Neon PostgreSQL 18.7 soportado por Hyperdrive (hasta 18.x).

### Límites relevantes (plan gratuito)
- **100,000 requests/día** para Pages Functions (compartido con Workers).
- **10 ms CPU por request** en free (vs 30 s por defecto en paid). El promedio es ~2.2 ms; auth/SSR típicamente 10–20 ms. **Riesgo:** funciones con scrypt (cost 16384) pueden superar 10 ms de CPU en free tier. Considerar plan Paid ($5/mes) o optimizar.
- **50 subrequests por invocación** (free) — las transacciones multi-query (bootstrapAdmins, migraciones) podrían exceder; pero el runtime de app hace 1–3 queries por request, bien dentro del límite.
- **128 MB memoria**, **64 MiB worker size**, **1 s startup**.
- **500 builds/mes**, **20,000 archivos estáticos**, **25 MiB archivo máximo**.
- **64 env vars por Worker** (free) / 128 (paid). Arkik usa ~11 variables ? OK.
- **Env var size 5 KB**.
- **Dominios personalizados:** 100 (free).
- **Requests a assets estáticos:** gratuitos e ilimitados.

### Costes
- Plan gratuito: $0. Suficiente para validación y tráfico bajo.
- Plan Paid: $5/mes base + $0.30 por millón de requests adicionales + $0.02 por millón de CPU-ms adicionales. Sin cargos por egress/bandwidth.
- **No se requieren servicios de pago para iniciar.** Hyperdrive está incluido en todos los planes (incluido free).

## 4. Adaptación requerida (archivos afectados)

### A. Reestructuración de rutas (sin cambio de lógica)
- Mover `api/**/*.js` ? `functions/api/**/*.js` (o `functions/**/*.js` según el path deseado).
- Cloudflare Pages auto-genera rutas desde el árbol de archivos bajo `/functions`.

### B. Adaptador HTTP (moderado)
- Crear un adaptador que convierta `onRequest(context)` en el par `(req, res)` que los handlers esperan, **o** reescribir los handlers para usar Web Request/Response.
- Opción recomendada: **adaptador pequeño** (`functions/_middleware.js` o helper en `_lib`) que construya un objeto `req` compatible (method, url, headers, body, socket.remoteAddress?`cf-connecting-ip`) y un objeto `res` compatible (status, json, setHeader, end) sobre la Web Response. Esto minimiza cambios en los 20+ handlers.
- `withCors` wrapper debe adaptarse para usar `context.request`/`context.env` y devolver `Response`.

### C. Variables de entorno
- `process.env` ? `context.env` (o variables de entorno de Pages, que se exponen como bindings). Con `nodejs_compat` y compat date = 2025-04-01, `process.env` está disponible, pero la práctica recomendada en Pages es `context.env`.
- `config.js` debe leer de `context.env` o de un global inyectado por el adaptador.
- `clientIp()`: reemplazar `process.env.VERCEL` por detección de Cloudflare (`cf-connecting-ip` header, siempre confiable en Workers). Eliminar la rama Vercel.

### D. Cookies / seguridad
- `Set-Cookie` vía Response headers (funciona igual).
- `isSecureCookieContext()` / `assertSecureCookieAllowed()`: Cloudflare siempre sirve HTTPS ? Secure cookies siempre. Simplificar: `isCloud = true` cuando `cf-connecting-ip` presente o env var `CLOUDFLARE` = 1.
- CSP y headers de seguridad: mover de `vercel.json` a `_headers` file o a middleware en `functions/`. Cloudflare Pages soporta `_headers` (max 100 reglas, 2000 chars por header).

### E. Rutas SPA (rewrites)
- `vercel.json` rewrites (`/admin` ? `/index.html`, etc.) ? `_redirects` file o Pages `_redirects` (max 2000 estáticos, 100 dinámicos). O configurar en dashboard.

### F. Base de datos
- Mantener `@neondatabase/serverless` (sin Hyperdrive) en la fase inicial: sin cambios en `db.js` ni en las queries/transacciones.
- Usar `arkik_app` como único rol runtime (ya es el diseño actual).
- Separación STAGING/Production vía env vars por entorno (Preview vs Production en Pages).
- `DIRECT_DATABASE_URL` y `DIRECT_ADMIN_DATABASE_URL` **nunca** en runtime de Cloudflare (solo CLI local).

### G. Archivos de configuración nuevos
- `wrangler.toml` o `wrangler.jsonc` (compatibility_date, compatibility_flags, env vars, hyperdrive binding si se usa).
- `.node-version` o env var `NODE_VERSION` para build (22.x).

## 10. Cierre

**Dictamen: `PORTABLE — MODERATE ADAPTATION`**

Arkik puede desplegarse en Cloudflare Pages + Workers manteniendo Neon como backend PostgreSQL. El esfuerzo es moderado y se concentra en un adaptador HTTP (handlers, CORS, cookies, IP, env) y en la reestructuración de rutas de `api/` a `functions/`. La lógica de negocio, autenticación, datos y seguridad no requieren cambios. El driver `@neondatabase/serverless` funciona en Workers; Hyperdrive es una optimización posterior opcional.

El plan gratuito de Cloudflare ($0) es suficiente para validación y tráfico bajo, pero el límite de 10 ms de CPU por request puede requerir el plan Paid ($5/mes) si las operaciones de scrypt exceden ese umbral. No se creó ningún recurso ni se modificó código en esta fase.

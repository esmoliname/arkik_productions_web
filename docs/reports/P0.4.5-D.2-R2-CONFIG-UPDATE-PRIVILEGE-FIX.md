## 1. Causa de R1-REG-01

La migración `db/migrations/007_least_privilege_refinement.sql` revocaba todo `UPDATE` sobre `public.config` para `arkik_app` (`REVOKE UPDATE ON TABLE public.config FROM arkik_app;`) bajo la premisa falsa de que `arkik_app` solo leía `config` (solo `SELECT` en `loadConfig`).

Esa premisa contradice el código real:

- `api/admin/pricing.js:28` → `service.putPricing(body, admin.role)`
- `api/_lib/service.js:726-729` → `repo.putConfigValue(client, 'pricing', 'overrides', nextOverrides)` y `repo.putConfigValue(client, 'pricing', 'rates', nextRates)`
- `api/_lib/repo.js:377-383`:
  ```sql
  INSERT INTO config (namespace, key, value, updated_at) VALUES ($1, $2, $3::jsonb, now())
  ON CONFLICT (namespace, key) DO UPDATE SET value = EXCLUDED.value, updated_at = now()
  ```

Cada actualización de precios/tarifas del Owner ejecuta un UPSERT sobre filas ya sembradas en `003_config_seed.sql`. Sin `UPDATE` (al menos sobre `value` y `updated_at`) el UPSERT falla con `42501 permission denied for table config`, rompiendo `PUT /api/admin/pricing`.

Además, `test/migration-007.test.cjs` codificaba la regresión como esperada (`REVOKE UPDATE` sin reposición de columnas).

---

## 2. Corrección aplicada

Archivo modificado: `db/migrations/007_least_privilege_refinement.sql`.

- Corregidos los comentarios falsos (preflight ítem 4 y sección 3) que afirmaban que `arkik_app` nunca escribía `config`. Ahora documentan que `arkik_app` escribe `config` vía `putConfigValue` y solo muta `value` y `updated_at`.
- Inmediatamente después de `REVOKE UPDATE ON TABLE public.config FROM arkik_app;` se añadió:
  ```sql
  GRANT UPDATE (value, updated_at) ON TABLE public.config TO arkik_app;
  ```
- `INSERT` y `SELECT` sobre `public.config` se preservan desde `004_least_privilege_grants.sql` (la 007 no los revoca). No se volvió a conceder `UPDATE` a nivel de tabla ni sobre `namespace`/`key`.

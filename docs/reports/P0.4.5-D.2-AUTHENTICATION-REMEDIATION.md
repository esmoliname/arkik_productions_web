## 3. Credential policy (target vs. current)

Target policy for NEW credentials (single factor):
- Minimum 15 characters.
- Allow at least 64 characters.
- Allow spaces, unicode, special characters.
- No artificial composition rules.
- No silent truncation.
- Reject malformed/excessive input safely.
- Per-admin independent credential; no shared/master/backdoor.

Current enforcement:
- Login: accepts any 1..64 chars (no minimum forced) — preserves legacy credentials.
- Bootstrap (`migrate.js`): enforces 6-char minimum for env-derived credentials.
- Rotation CLI (`manage-admin-pins.js`): enforces 6-char minimum.

Decision: the 15-char minimum is NOT enforced in D.2 because bootstrap/rotation flows
and their tests still use 6-char env PINs, and forcing 15 now would block existing
administrators during transition. The constant and validation hook are documented here
for the next authentication phase (MFA/passphrase rollout), where rotation will require
>=15 and legacy credentials will be rotated via the existing `admin:rotate` flow.

## 4. scrypt parameters vs OWASP

Current: `cost=16384 (2^14), blockSize=8, parallelization=1, keylen=64, salt=16 bytes, maxmem=64 MiB`.

OWASP reference minimum: N=2^17, r=8, p=1. Current N is below the OWASP floor.
However:
- Changing N affects stored-hash compatibility and computational cost in the Vercel
  serverless runtime (cost=2^17 ≈ 8x CPU/memory per login).
- No algorithm change was performed in D.2 (per prompt: "No cambies de algoritmo
  automáticamente"). The versioned hash format (`scrypt$N$r$p$salt$derived`) already
  supports per-credential parameters, so a future migration can raise N for NEW
  credentials only while keeping legacy hashes verifiable.

Recommendation for next phase: raise cost to 2^17 for newly rotated credentials and
add a `needsRehash` check at login (verify with stored params, re-hash on success if
below target). No migration run in D.2.

## 5. Login protection (already present, verified)

- Rate limiting per IP + per IP+role (service.login): 10/hour IP, 5/15min per role.
- Env-PIN fallback path: 5 attempts then progressive lockout (30s..15min), per origin+role.
- Generic error messages (`Credenciales inválidas.`) — no user enumeration.
- Audit logging without secrets (ADMIN_LOGIN / ADMIN_LOGIN_FAILED).
- Credential lock fields: failed_attempts, lock_level, locked_until.

## 6. Sessions (already present, verified)

- Cookie: `__Host-session` (Secure) on Vercel/cloud/production; `arkik_session` otherwise.
- HttpOnly, SameSite=Strict, Path=/, Max-Age=900 (15 min sliding).
- Token stored only as HMAC-SHA256 (hashToken) in admin_sessions.
- Sliding expiry refreshed at most once/minute (TOUCH_AFTER_MS).
- Logout deletes session row; post-logout replay denied.
- Session ID rotated on authentication (new token per login).

D.2 addition: `SECURE_COOKIES=1` env flag enables Secure on staging/preview outside
Vercel when TLS is terminated by the operator. Default behavior unchanged (preserves
local http://localhost smoke tests). See `api/_lib/config.js` `forceSecureCookies`.

## 7. MFA / Passkeys proposal (NOT implemented in D.2)

Rationale for deferral: partial MFA without secure recovery would weaken security.

Proposed architecture for next phase:
1. Passkeys/WebAuthn as primary second factor (preferred).
   - Requires a stable HTTPS origin (RP ID = production domain). Vercel Preview
     domains (`*.vercel.app`) can serve as RP ID for testing only; production
     domain required for real users.
2. TOTP as fallback where passkeys are unavailable.
3. Schema changes (forward-only migration 008+):
   - `admin_credentials`: add `mfa_type` (none/totp/webauthn), `mfa_secret_enc` (encrypted at rest), `mfa_enrolled_at`.
   - New table `admin_webauthn_credentials` (credential_id, public_key, counter, transports, created_at).
   - Recovery codes (hashed, single-use) stored separately; never printed in logs.
4. Enforcement: require MFA only after successful enrollment + grace period; never
   disable MFA via env flag. Recovery requires owner + out-of-band verification.

No MFA code, secrets, or dependencies were added in D.2.
